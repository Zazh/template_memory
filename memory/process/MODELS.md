# Модели и эффорт по ролям (сменный листок)

Единственное место, где роли процесса привязаны к конкретным моделям. Заголовок
промпта в SESSION.md несёт роль и уровень, а составитель бэклога вписывает туда
же актуальные модель и эффорт из этого файла («критик — уровень review · Opus 5.5 ·
effort xhigh») — владелец копирует команду, не сверяясь с таблицей. При смене
поколения моделей правится этот файл и заголовки промптов незакрытых блоков
активных бэклогов (актуализирует критик очередного блока).

Актуализировано: **2026-10-04** (поколение Claude 5: Opus 5.5 — дефолт конвейера, сессии
идут на нём с 2026-09-29; Fable 5.1 — точечно). Пересматривать при выходе нового
поколения или смене цен.

| Уровень | Роль в конвейере | Модель | Reasoning-эффорт |
|---|---|---|---|
| **light** | Мелкая механика по детальному ТЗ, S-режим без риска | Opus 5.5 | medium |
| **build** | Исполнитель блока (дефолт) | Opus 5.5 | high |
| **review** | Критик, приёмка, каталожные ревью, гейт перед прод-деплоем | Opus 5.5 | xhigh |
| **deep** | Составитель бэклога, бриф-интервью, диагностика с высокой неопределённостью, архитектурные развилки, security-критика публичной поверхности | Fable 5.1 | high/xhigh |

Принципы:

- **Дефолт — Opus 5.5**: агентный кодинг и код-ревью, дешевле Opus 5 ($4/$20 против
  $5/$25) при той же ёмкости. Эффорт ставить ЯВНО по таблице: у Opus 5.5 дефолт API —
  `medium` (у Opus 5 был `high`); low/medium сильны — простую механику не гнать на high.
- **Fable 5.1 — точечно, не дефолт** (цена ×2,5 к Opus 5.5, ходы длиннее): там, где нужна
  неопределённость и критика, а не исполнение чек-листа. Исключение — блоки с
  высокой ценой ошибки наружу (деньги, массовые отправки, миграции данных): их
  критика и приёмку допустимо поднять до Fable 5.1 (уровень deep) решением владельца
  в §5 бэклога.
- Триггер-слова (`ultrathink`, `ultracode`) действуют только в **набранной
  команде** — их вписывают прямо в команду внутри ```-блока промпта SESSION.md
  (например `/critic <иниц.> 4 ultracode`); упоминание в тексте файла режим не
  включает, пометка уровня в заголовке — тоже.
- `ultrathink` — сессия дольше думает; `ultracode` — сессия получает право на
  мультиагентные workflow (в разы дороже). Стандарт: **L-блоки** — исполнитель
  с `ultrathink`, критик и приёмка с `ultracode`; M-блокам не положено (xhigh
  достаточно).
- Клинап-сессия L-блока — уровень build; ревью-сессии — уровень review.

## Факты по моделям

Сверено 2026-10-04 по справке API Anthropic (срез 2026-09-25). Цены — $/MTok на первой
стороне API; кэш-чтение у Opus 5.5 и Sonnet 5.5 — 0,20.

| Модель | ID | Вход / выход | Позиционирование |
|---|---|---|---|
| **Fable 5.1** | `claude-fable-5-1` | 10 / 50 | Самая способная широкодоступная модель (Mythos-класс, над Opus). Преемник Fable 5 в том же тире и по той же цене; тот же токенизатор. Контекст 1M, выход до 128K |
| Fable 5 | `claude-fable-5` | 10 / 50 | Предыдущий Fable, обслуживается; в новых сессиях не нужен — 5.1 без доплаты |
| **Opus 5.5** | `claude-opus-5-5` | 4 / 20 | Дефолт конвейера: преемник Opus 5 в линейке Opus, дешевле его при тех же контексте 1M, выходе до 128K, токенизаторе и наборе фич |
| Opus 5 | `claude-opus-5` | 5 / 25 | Предыдущий Opus, обслуживается; новые сессии — на 5.5 |
| Opus 4.8 | `claude-opus-4-8` | 5 / 25 | Legacy, поколение 4.x; в конвейере не используется |
| Sonnet 5.5 | `claude-sonnet-5-5` | 2 / 10 | Дешёвый воркер для сабагентов/массовой механики, не для ролей конвейера; контекст 1M, выход до 128K (Sonnet 5 — предыдущий, та же цена) |

Нюансы Opus 5.5, важные для сессий:

- **Thinking всегда включён и не выключается** (явное отключение и бюджет токенов —
  ошибка API); глубина — только эффортом `low`…`xhigh`, `max`. **Дефолт API — `medium`**,
  у Opus 5 был `high`: эффорт сессии выставлять явно по таблице уровней, иначе
  build-сессия идёт на medium.
- **Fast mode** — та же модель, вывод до ×2,5 быстрее; по API цена ×2 (8/40), в Claude
  Code — `/fast`. Включать точечно (долгий однопоточный прогон), не держать по умолчанию.
- **Токенизатор общий** с Opus 5 / 4.8 и Fable 5 / 5.1 — сметы в токенах при переходе
  между ними не пересчитывать, разница только в цене за токен.
- **Классификаторы безопасности шире**, чем у Opus 5 (кибер, био, извлечение
  рассуждений): отказ приходит как `stop_reason: refusal`, в сессии — как отказ без
  ошибки. Лечится явным контекстом задачи в промпте (что и зачем делаем), а не сменой
  модели — у Fable 5.1 классификаторы тоже есть.
- Breaking changes API Opus 5 → 5.5 (снят принудительный `tool_choice`, thinking-блоки
  привязаны к модели и диалогу, computer use только новым toolset) касаются только
  собственного кода на API — у нас его нет (LLM в продукте не используем).

Нюансы Fable 5.1, важные для сессий:

- **Расход на задачу выше не только из-за тарифа**: более долгие автономные ходы (минуты
  на запрос, больше самопроверки) — это поведение модели; при общем токенизаторе задача
  на Fable обычно съедает больше токенов, чем на Opus 5.5.
- **Thinking всегда включён**, глубина управляется эффортом (`low`…`xhigh`, `max`).
  Для рутины на Fable 5.1 low/medium часто достаточно — но рутину всё равно ведём на
  Opus 5.5 (дешевле при том же качестве).
- **Промпты для прежних моделей часто слишком директивны** и снижают качество
  Fable: формулировать цель и критерии готовности, а не пошаговую инструкцию. Для
  ролей конвейера это уже так — ТЗ описывает результат и критерии приёмки.
- Fast mode — только Opus 5.5 / 5 / 4.8; на Fable недоступен.

В Claude Code: модель — `/model`; эффорт — `claude --effort <уровень>` при запуске или
`/effort` внутри (сохраняется как дефолт — после спец-сессии вернуть); ускоренный вывод —
`/fast` (только Opus).
