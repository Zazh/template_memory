# Фронт — живые доки

## Назначение {#purpose}

Каталог описывает фронт проекта: что есть на каждом экране, по каким правилам он работает и
где его макет. Читают сессии конвейера (составитель, исполнитель, критик, приёмка) — секцию
по якорю, а не файл целиком. Бэкенд-модель — в `architecture/`, здесь — только то, что видит
и делает фронт. <!-- Заполнить первым бэклогом с UI: репо фронта, приложения, где кит. -->

## Правила живых доков {#rules}

Канон для каталога (гайды процесса ссылаются сюда; механика гейта —
`process/BACKLOG-GUIDE.md`, «Гейт живых доков»).

- **Один файл — один экран или подсистема.** Потолок — 40 КБ (`design.md` — тоже 40, этот
  README — 15); потолок записан в `lint-manifest.txt`, lint `size` держит его на каждом
  коммите. Не влезает — делить **по предмету**, не по дате; новый файл — строкой в карту
  ниже и в манифест.
- **Скелет обязателен** — восемь секций в фиксированном порядке с фиксированными якорями
  (ниже, «Скелет»); пустая секция остаётся строкой «—».
- **Заголовки — без дат, номеров блоков и ID задач** (lint `heading`). Откуда пришло
  правило — видно в `decisions/`, а не в заголовке.
- **История — не в живом доке.** Надгробия, снесённые потоки, «как пришли к решению» — в
  `decisions/<лог>.md` под заголовком-источником; в файле экрана — одна строка-ссылка в
  секции «История». Действующее 🔴-правило — не история, даже если в тексте есть дата
  (lint `tomb` не пропускает знак надгробия в файлах манифеста).
- **🔴-правила — в секции «Правила» своего экрана**, не абзацем в конец документа. Критик и
  исполнитель правят раздел по скелету, а не дописывают хвост.
- **Ссылки — якорями:** `frontend/<файл>.md#<якорь>`, путь от корня `memory/`; слаг —
  `[a-z0-9-]+`, уникален в файле. Lint `anchor` проверяет, что файл есть и заголовок с таким
  `{#якорем}` в нём ровно один. Номера разделов («§ 27») не использовать — они плывут.
- **Новый экран** = новый файл по шаблону `process/templates/screen-doc.md` + строка в карте
  каталога + строка `frontend/<файл>.md 40` в `lint-manifest.txt` — в том же коммите.
- **Дизайн — в `design.md`:** адреса макетов Figma (node-id 1440/393) и статус —
  `frontend/design.md#screens`, токены, канон дорисовки (`frontend/design.md#canon`), дельты
  код↔макет (`frontend/design.md#deltas`). Файл экрана в секции «Макет» ссылается на
  подраздел своего экрана в `design.md`, node-id не копирует.

## Скелет файла экрана {#skeleton}

Шаблон — `process/templates/screen-doc.md`. Порядок и якоря фиксированы, поэтому ссылка
`<файл>.md#rules` осмысленна для любого экрана:

```
# <Экран или подсистема>                  H1 без дат и ID
## Назначение {#purpose}                 2–5 строк: что это, для кого
## Маршруты {#routes}                    пути SPA, гварды, вход/выход, редиректы
## Макет {#mockup}                       ссылка на строку design.md: node-id 1440/393, статус, дельты
## Компоненты кита {#kit}                какие примитивы/рецепты кита, что не на ките
## Данные и домен {#data}                ручки API, файлы кода (пути), сторы/домен
## Правила {#rules}                      🔴-правила, канон поведения — самое ценное
## Тесты и e2e {#tests}                  юниты, сценарии e2e поимённо, как гонять
## История {#history}                    ОДНА строка: ссылка на decisions/<лог>.md#<якорь>
```

Подразделы внутри секций — `###` со своими якорями (шаги, сводка…), без дат и ID.
Бэкенд-поддомен (`architecture/<модуль>/*.md`) — тот же скелет, но «Маршруты» → «Ручки и
схема» (якорь `api`), «Макет» и «Компоненты кита» опускаются.

## Как искать {#find}

- Якоря каталога: `grep -rn '{#' frontend/` — оглавление всех файлов разом.
- Факт: `grep -rln 'слово' frontend/`, затем `grep -n` в найденном файле.
- Читать секцию по якорю, не файл целиком; история — только по ссылке из «Истории».
